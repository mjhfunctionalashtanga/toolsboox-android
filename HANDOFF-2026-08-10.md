## What landed, and why

Grouped by the thing it was solving rather than by build, because the builds interleave.

### The ritual walk matches Daily again
`RitualWalk` (new, `plugin/calendar/ot/`). The walk had been a list of note-page keys inside
`CalendarDayFragment`; Daily was reordered and the stepper was not, so the Day Skipper silently
stopped visiting four stations. Two of them — Quick Wins and Missed Connections — are not day pages
at all, so a walk that could only name page keys could never have contained them.

A `Station` now knows how to be *arrived at* (page key or nav action). Both surface stations gained
↑/↓ on their rails; Missed Connections had an entirely empty rail, which is why it read as skipped.
Eight tests assert the order literally.

**Self Executive is back on the walk on Michael's instruction**, against its usage count (4 written
days in 124). Not a reversal of the measurement: the measurement could see how often a page was
*written* and could not see what it was *for*.

### Handwritten replies send the handwriting
`SmtpClient` learned `multipart/mixed`. The Write-piece reply had been OCR'ing the page and sending
the transcription, so a letter written by hand arrived as typed text. The recognised text still
leads the message — it is what threads and searches — and the picture rides with it.

The no-attachment path is deliberately unchanged (single-part, not a one-part multipart): this is
the one function that builds every message the client has ever sent. Five tests cover the wire rules
that actually get mail rejected — 76-column base64 wrap, closing boundary, part order, dot-stuffing
inside a part.

### The Map became a page, and links became edges
`GramComposer` (new) writes a GRAPH onto a note page as ordinary objects: each node a gram carrying
`sourceLink` (so provenance is live and tappable), each node a text box (so the page is searchable),
each edge a connector in the page's own ink (so it erases and merges like anything drawn). Two
layouts — GRID for the Map, COLLAGE for research. Deterministic scatter, so a page you recognise is
a page you can return to.

`LedgerLinks` (new) is the twin of `LedgerTags`: `[[wiki links]]` harvested off the **same OCR pass**,
recorded against (date, page), and — the load-bearing part — joined into `ConnectionStore`. So:

> handwrite `[[Collider]]` → OCR catches it → Collider ↔ this page joins the rhizome →
> the pair is an edge on the Map → the Map saves to a Grid note with provenance intact

The pattern is strict on purpose. This runs over handwriting recognition, where a lone bracket is
among the likeliest characters to be hallucinated; a false tag is noise in an index, a false link is
a claim that two of Michael's ideas belong together. Both brackets required, a letter inside, code
excluded. **An unresolved link is not an error** — linking forward to something unwritten is ordinary
in a handwritten ledger, and the index shows it as *owed* (◇) with an offer to write it.

Link index + backlinks live in Notes beside Tags. Backlinks list *inside* the row, not behind it.

### The shelf points at the library instead of copying it
Michael's instruction: *"We can declare a folder to use in app as the books folder."* That replaced a
worse plan (a book model with imported copies) which would have forked a library Calibre, Syncthing
and BooxDrop already maintain.

`BookshelfSource` is a POINTER: default is the app's own directory, a declared SAF tree is anything
else. Copy-on-open, not copy-on-declare. Depth-bounded at three levels (pointed at storage root, an
unbounded walk is a hang on e-ink). A revoked declaration degrades to the default shelf rather than
an empty one — that failure looks exactly like "the app lost my books".

`BookshelfFragment` (new surface) — two bands: **what you read in the almanac's window**, then the
whole library by its own folders. `BookOpens` records reading here rather than stamping file mtimes,
because you cannot stamp a file inside a declared tree and touching the Calibre library to note a
read would push a library across the mesh. `BookCovers` extracts EPUB/CBZ art, renders PDF page one,
and draws a legible card for everything else.

`OpdsCatalog` (new) is the Android twin of `App/OPDS.swift`. **It reads the config the settings sync
was already carrying**: `SettingsBackup` had been holding `opds.{url,user,pass}` as an iOS-only
section for months, so the catalog was configured on every Boox and nothing could open it. That
needed one new door — `SettingsBackup.carriedSection` — on the principle that "Android has no home
for this" is a statement about a moment, not forever.

**SAX, not the pull parser**: `XmlPullParserFactory` is an unimplemented stub in Android's unit-test
jar, so a pull-parsed catalog could only ever be tested on a device — and this parser's entire risk
is other people's XML.

### Notes as real Markdown
`NotesMirror` (new). The rule, and it is the whole design:

> **Text round-trips because text IS the source. Ink exports because the strokes are the source and
> a picture of them is not.**

A folder where some edits stick and some silently vanish is worse than one where the rule is obvious.
Text notes become `.md` with front matter (newer-wins by `updated`); ink pages copy out as PNG plus
recognised text, one-way, saying so in the file's first line.

**Explicitly NOT a decomposition of the day file.** `CalendarDayMerger` merges on it, tombstones
delete against it, the fixtures pin it, both forks agree byte-for-byte. Splitting a day into one file
per note means rewriting the merge on two platforms to gain a filename.

`[[links]]` needed no translation — Obsidian spells them the way `LedgerLinks` does.

### Ask's outputs
Synthesize and Brainstorm prompts landed in `PersonaStore` verbatim as approved. Both carry the
Missed Connections clause — which forced `discover` out of `MissedRhizomesFragment` into
`MissedRhizomes` with a `missed_connections` tool, because **a prompt that names material the model
cannot reach produces invention, not restraint.** The surface and the model now read one function.

`PickHarvest` (new): a link in, a Pickings board out. Quotes lead, notes follow. The integrity rule
is verbatim-or-nothing — paraphrasing into quotation marks is the same failure as inventing a
citation, and worse here because these cards end up beside things Michael wrote by hand and the page
will not remember which was which. The parser drops orphan bullets rather than guessing which list
they belong to.

`ResearchAssistant` (earlier in the run) lands curated, cited sources as a Jots collage.

### Smaller, but each was a real complaint
- **The pen is a habit, not a setting.** Width and colour were never persisted (only `penStyle` was),
  so every surface reset them — picking bold red worked until you turned the page. `AnnotationPen`
  gives the annotation pad the same memory. The rail row now names the pen: "Pen · fine calligraphy".
- **The gyro follows the device.** `sensorPortrait` (inherited from upstream, with a lint suppression
  acknowledging it) rotates only portrait↔upside-down, so landscape was never on offer. Now
  `fullUser`, which still obeys the device rotation lock.
- **A podcast opens its page and plays.** It used to return early on the reasoning that a podcast is
  listened to rather than read — wrong about podcasts, where the show notes are the reason you went
  looking. `LedgerPlayerRail` moves the transport into the rail; the modal survives for the reader.
- **A link is a thing you attach**, so it sits on the ＋ Add media door; `[[a note]]` typed where a
  URL goes makes the same card, so a link pasted and a link handwritten are one edge.
- **The text-size panel stays open** — it was `setItems`, and a list dismisses when you pick from it.
  Right for destinations, wrong for a dial.
- **＋ New note takes your last template.** The row already carried a fold with all five, so the
  dialog was a second way to answer an answered question.
- **Two-page spread** on the reader (foliate always could; the setting had no door).
- **Roster → Event Attendees**, and "Record Prompt" now says what it does.

## iOS parity — the big job

Michael, 2026-08-10: *"Once those have been addressed, we can bring the iOS version to parity."*

The wire is unchanged, so nothing is broken by the gap; but four of the new objects were written to
be twinned **while they are still small**, and they are getting less small.

**Port in this order** — each is independently useful and the later ones build on the earlier:

1. **`RitualWalk`** → the walk + Daily's order. iOS's `PlannerPage` already carries every page the
   walk needs; Quick Wins and Missed are separate surfaces there too, so the Station shape ports
   directly. Small, and it fixes the same Day Skipper bug.
2. **The IA restructure** (1.06.28–1.06.31 equivalents) in `App/SidebarMenu.swift` — that file is the
   twin of `LedgerDirectory.kt`, and `directorySections` (~lines 305–470) is where it all lives. iOS
   still has Flow, Garden with Roots/Sprouts/Seeds, Quick Wins under Desk, and no Sites or Fluent
   grouping. Android's canonical tree is dumped in this session's notes; re-derive it from
   `ledgerDirectoryFolders`.
3. **`LedgerLinks`** — the twin of `LedgerTags`, which iOS already has. Hook the same OCR pass. iOS
   records exact Apple Vision word boxes where Android estimates them, so the occurrence rects will
   be better there, not worse.
4. **`GramComposer`** — needs rewriting rather than translating: a connector is a `PKStroke`, not a
   `Stroke`. This is the seam where the forks have bitten us before (see the nib/geometry-key work in
   build 49). Do it with the fixtures open.
5. **`BookshelfSource` + the shelf surface** — iOS has `App/OPDS.swift` already and its own reader;
   the declared-folder idea maps to a security-scoped bookmark rather than a SAF tree.
6. **`NotesMirror`** — last, because it benefits most from the links being in place first.

**Do not** port the `SettingsBackup.carriedSection` direction blindly: on iOS the OPDS config is
native, so the flow is the reverse (iOS should keep writing it; Android reads it).

## Gotchas worth carrying forward

- **Gradle tasks are variant-scoped.** `compileDebugKotlin` and `testDebugUnitTest` DO NOT EXIST here
  and fail with an "ambiguous" error that contains no `e:` line — so an error-grep comes back empty
  and reads as a clean build. Use `compileProdStandardDebugKotlin` /
  `testProdStandardDebugUnitTest`, and treat `BUILD SUCCESSFUL` as the positive signal. This produced
  two false "compiles clean" reports on 2026-08-03.
- **Ship debug, never release.** There is no keystore on this machine; the debug key produces package
  `com.toolsboox.mjh.debug`, which is what every device has. A release build changes the package and
  costs local data. Build from a clean worktree at HEAD, `cp local.properties` in first.
- **A nested `typealias` is illegal in Kotlin** and fails as a bare `[ksp] IllegalStateException` with
  no message. Use an import alias.
- **Measure the device before theorising.** The rail-column bug was settled in one screenshot plus a
  first-ink scan after three rounds of wrong reasoning from the code. `adb shell screencap` +
  `uiautomator dump` are both available and cheap.
- **Do not ship plausible fixes.** The build-48 pressure fix and two readings during the rail
  investigation were all confident and wrong. If it cannot be proven, say so in the commit and in
  the report.
